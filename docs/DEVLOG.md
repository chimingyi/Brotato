# AI 游戏开发日志

这里记录每一步做了什么、为什么这样做、怎样验证，以及下一步准备做什么。

## 2026-08-21｜第 1 步：让角色出现在屏幕上并移动

### 本步目标

先完成最小的互动：打开网页后，玩家能够控制角色在场地中移动。

### 做了什么

- 选择原生 HTML、CSS 和 JavaScript，不依赖游戏引擎。
- 用 Canvas 创建 16:9 的游戏场地。
- 用简单图形画出原创的薯星探险员，不使用外部素材。
- 加入 `WASD` 和方向键移动。
- 使用“每秒速度 × 两帧之间的时间”计算位移，让不同性能的电脑上速度接近一致。
- 限制角色位置，避免跑出屏幕。
- 加入开始界面、计时、生命条和空格暂停。

### 为什么从移动开始

游戏开发最重要的办法是把大目标拆成能马上验证的小目标。角色移动是玩家与游戏的第一次互动，也是后面敌人追踪、碰撞和拾取系统的基础。

### 怎样验证

1. 启动本地网页服务器。
2. 打开游戏，点击“开始冒险”。
3. 分别按 `WASD` 和方向键。
4. 检查斜向移动是否不会比横向移动更快。
5. 走到四条边，检查角色是否会留在场地内。
6. 按空格，检查计时和移动是否暂停。

### 遇到的问题

- 本地仓库还没有设置 GitHub 远程地址。
- 通过 HTTPS 读取远程仓库时需要 GitHub 登录，因此暂时不推送。

### 下一步

加入第一种敌人：敌人从场地外出现，并自动追踪玩家。

## 2026-08-21｜第 2 步：加入敌人与自动战斗

### 本步目标

建立最小战斗循环：敌人出现并追踪玩家，玩家自动攻击，双方都能造成伤害。

### 做了什么

- 敌人会随机从场地四周出现，并朝玩家移动。
- 生存时间越长，敌人的移动速度和生命值会缓慢增加。
- 玩家会寻找最近的敌人，自动发射种子子弹。
- 子弹与敌人使用圆形距离检测完成碰撞。
- 敌人死亡后增加击败数量，并产生简单粒子效果。
- 敌人碰到玩家会扣除生命；短暂无敌时间可避免一帧内连续扣血。
- 生命归零后显示本局时间和击败数，可以重新开始。
- 页面失去焦点时自动暂停，避免玩家切换窗口后被敌人偷袭。

### 这一步学到的概念

- **数组**：用来保存当前场上的所有敌人、子弹和粒子。
- **游戏循环**：每一帧更新位置、检测碰撞，然后绘制新画面。
- **状态**：开始、暂停和失败是三种不同的游戏状态。
- **难度曲线**：根据生存时间逐渐调整敌人强度，而不是突然变难。

### 怎样验证

1. 开始游戏后等待约 2 秒，确认敌人从边缘出现。
2. 不按攻击键，确认玩家会自动朝最近敌人发射子弹。
3. 观察击败数字是否增加。
4. 故意不移动，确认生命会下降并最终显示失败面板。
5. 点击“再试一次”，确认时间、生命和击败数全部重置。

### 下一步

让敌人掉落能量，加入经验值、升级和“三选一”强化。

## 2026-08-21｜第 3 步：经验与三选一升级

### 本步目标

让战斗产生奖励，玩家可以在一局中逐渐形成自己的成长路线。

### 做了什么

- 敌人死亡时掉落青色能量晶体。
- 晶体进入拾取范围后会加速飞向玩家，远处的晶体也会缓慢靠近，避免永久留在场上。
- 加入经验条、等级和逐级增加的升级需求。
- 升级时暂停战斗，并随机显示三个强化选项。
- 第一批强化包括：伤害、攻速、移速、生命、拾取范围和多重射击。
- 重新开始时会重置所有升级，保证每一局都从相同起点开始。

### 这一步学到的概念

- **数据驱动**：所有强化用统一的数据结构保存，增加新强化时不需要重写界面。
- **随机抽取**：从可用强化中洗牌后取三个，并排除已经达到上限的多重射击。
- **暂停状态**：选择强化时停止战斗，选完后继续，而不是另开一个游戏循环。

### 怎样验证

1. 击败敌人，确认地面出现青色菱形晶体。
2. 靠近晶体，确认它会被吸向角色并增加经验。
3. 经验条满后，确认战斗暂停并出现三个不同选项。
4. 选择强化，观察对应数值或战斗效果是否发生变化。
5. 重新开始，确认等级、经验和强化都恢复初始状态。

### 下一步

加入不同类型的敌人和另外两种武器，让每局的战斗变化更丰富。

## 2026-08-21｜第 4 步：敌人种类与武器构筑

### 本步目标

避免战斗一直重复同一种情况，让玩家需要根据敌人和随机强化调整选择。

### 做了什么

- 保留基础孢子敌人，15 秒后加入速度快但生命低的疾行虫。
- 35 秒后加入移动慢、生命高、碰撞伤害高的岩壳怪。
- 不同敌人使用不同的形状、颜色、体型和属性。
- 受伤敌人头顶会显示小生命条，重装敌人更容易看出战斗进度。
- 新增“守护叶片”：叶片环绕玩家，对靠近的敌人持续造成伤害。
- 新增“星芒爆发”：每隔几秒向四周发射一圈星芒，升级后弹量和伤害增加。
- 三种武器共用已有的碰撞和粒子系统，减少重复代码。

### 这一步学到的概念

- **敌人模板**：类型决定基础属性，时间难度再统一放大属性。
- **复用函数**：所有武器都通过相同的击败函数掉落经验和增加击败数。
- **冷却时间**：环绕叶片给每个敌人设置命中冷却，防止每帧都计算一次伤害。

### 怎样验证

1. 生存超过 15 秒，确认橙色小型疾行虫出现。
2. 生存超过 35 秒，确认灰色大型岩壳怪出现。
3. 升级时选择守护叶片，靠近敌人观察叶片造成伤害。
4. 选择星芒爆发，观察周期性的环形弹幕。
5. 重新开始，确认两种额外武器都需要重新获取。

### 下一步

补齐手机触控、声音反馈、胜利条件、最高纪录和完整结算界面。

## 2026-08-21｜第 5 步：手机、音效、结算与最终测试

### 本步目标

把核心玩法整理成一款有开始、有过程、有结束，并且电脑和手机都能玩的第一版游戏。

### 做了什么

- 加入手机虚拟摇杆，拖动控制方向，松手后自动回到中心。
- 用 Web Audio 现场生成射击、拾取、升级、受伤、失败和胜利音效，不需要下载音频素材。
- 加入音效开关，并遵守浏览器“用户点击后才能播放声音”的限制。
- 一局目标设为 5 分钟，坚持到最后会显示胜利结算。
- 失败和胜利都会记录生存时间与击败数，并可以重新开始。
- 使用浏览器本地存储保存最高生存纪录。
- 手机开始界面会隐藏摇杆，开局后再显示，避免挡住按钮。

### 实际测试结果

- 桌面首次运行 8 秒：击败 5 个敌人，生命 100，控制台 0 个错误。
- 成长测试 22 秒：升到 2 级，出现 3 个不同强化，选择后战斗正常继续。
- 内容测试 39 秒：疾行虫和岩壳怪均已出现，等级 4，击败 33 个敌人。
- 失败测试 45 秒：正确显示结算面板和“再试一次”按钮。
- 手机测试尺寸：390 × 844；页面横向滚动宽度等于屏幕宽度，摇杆可见并能接收拖动。
- JavaScript 语法检查通过，HTML、CSS、JavaScript 均能由本地服务器正常读取。

### 测试发现并修复的问题

1. 生命值被最后一次伤害扣到 0 以下时，界面曾显示负数；现在最低显示为 0。
2. 手机开始页面的按钮曾与经验条重叠；现在隐藏冗长说明并压缩布局。
3. 手机摇杆最初在开始前出现；现在只在正式开局后显示。
4. 一次 42 秒的自动化检查超过测试工具单次时间限制；之后拆成短测试，确认这是测试连接超时，不是游戏崩溃。

### 第一版结论

第一版核心功能已经完成并通过本地测试。剩余发布工作是登录 GitHub、推送仓库并开启 GitHub Pages。

## 2026-08-21｜v2 第 2 步：完成第一波玩法闭环

### 这一步学到的概念

- **状态机**：用明确阶段控制哪些界面和规则正在运行，避免战斗、升级和商店同时响应。

- **可重复测试**：本地测试参数能稳定制造材料和升级机会，避免靠随机结果判断功能是否正确。
